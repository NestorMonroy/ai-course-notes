\section{统一视角：自我改进闭环}

本讲可以压缩成一个四阶段循环：

\begin{enumerate}
    \item \textbf{Generate}：模型或多个 Agent 产生候选动作、解答或计划；
    \item \textbf{Verify}：测试、奖励模型、规则或环境信号评估候选；
    \item \textbf{Select / Act}：选择候选并在环境中执行；
    \item \textbf{Update}：把反馈用于当前轨迹修正、记忆更新或参数训练。
\end{enumerate}

\begin{importantbox}{整门课程的概念地图}
Test-time scaling 主要改进 Generate 与 Select；robust verification 改进 Verify；tool use 和 planning 改进 Act；RL 与 synthetic data 把反馈写回参数；memory 与 continual learning 把经验跨任务保留。所谓 self-improving agent，就是让这条链路能稳定、可度量地循环。
\end{importantbox}

\subsection{设计一个自我改进系统时的检查清单}

\begin{itemize}
    \item 候选多样性来自哪里，是否只是重复生成相同错误？
    \item verifier 是否比 generator 更可靠，还是共享同一盲点？
    \item 反馈是立即、延迟，还是只能用代理指标近似？
    \item 哪些动作可逆，哪些动作需要权限或人工确认？
    \item 额外计算带来的边际收益是否覆盖成本和延迟？
    \item 更新会不会导致 reward hacking、遗忘或能力漂移？
\end{itemize}

\subsection{本章小结}

把模型、验证器、工具和更新机制拆开后，可以更清楚地定位系统瓶颈。很多“模型不够聪明”的失败实际上来自验证器、状态管理、工具接口或预算分配，而不一定需要重新训练更大的基础模型。
