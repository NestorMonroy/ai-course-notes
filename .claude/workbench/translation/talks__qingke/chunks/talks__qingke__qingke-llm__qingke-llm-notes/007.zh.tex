\section{持续学习与 Memory}

\subsection{Continual Learning 的工程挑战}

\textbf{谢天宝}：以 Cursor 为例，它做了简单的 Continual Learning（Type 补全），但周期不实时（几小时更新一次），且面临 messy signal、小 batch size 下有效梯度、灾难性遗忘、恶意攻击等问题。核心问题是：\textbf{过去我们训完模型就 freeze 做 inference，从不在 inference 时更新参数}——这是一个巨大的范式差异，也是非常大的研究方向。

\textbf{曹玉}：从逻辑上说 ``FLOPs for Continual Learning'' 是自然且和谐的——用 FLOPs 换持续的智能提升。但工程挑战巨大：用什么方法去 Learn（LoRA？Sparse Update？）、能否做到 Per User Per Model 的 Serving？希望 2026 年有机会了解哪些模型架构或方式能真正把 Test-Time Training 做出来，而非仅停留在理论推导和小 toy example 上。

\subsection{Parameter-based vs Context-based 两条路}

\begin{knowledgebox}{薛福昭：不搞花里胡哨，直接用 Context}
Lifelong Learning 有两条路：
\begin{enumerate}
  \item \textbf{Parameter-based}——LoRA / MoE 加 Expert / Embedding Bank。风险：模型越大越不稳定，小 batch size 的 backpropagation 很 risky，长期使用体验可能退化。
  \item \textbf{Context-based}——搞一个 Prompt Database（类似 Memory Retrieval），把历史写进去。唯一缺点是 context 很长——\textbf{但长 context 本质上还是 FLOPs}，回到开头的原则。
\end{enumerate}
建议：不要花里胡哨，直接搞成 context + retrieval。模型的 knowledge 更新就交给周期性的新版本发布（反正现在几个月就出一个新 model）。
\end{knowledgebox}

\textbf{刘子伟}：大模型可能像一个 OS——包含不同区域，某些参数应慢更新（Low-frequency knowledge），某些应快更新（High-frequency knowledge）。早在 20--30 年前就有 Slow Weight / Fast Weight 的概念（Hinton 等人）。此外，不同领域对 Long-tail Knowledge 的需求不同，某些 key application 一定需要在模型/数据层面考虑这个因素。数据天生是长尾分布的，低频部分不动、高频部分持续更新——这种 dynamics 值得深入研究。

\subsection{本章小结}
Continual Learning 是下一代 AI 的关键能力，但面临稳定性、工程复杂度、Serving 成本三重挑战。Context-based 方案更安全但需要长 context 支持；Parameter-based 方案更灵活但风险更大。
