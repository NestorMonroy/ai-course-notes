\section{系统拆解：Agentic Loop、Memory 与 Harness}

访谈中大量内容围绕一个朴素但实用的系统观：把 Agent 看成一个循环体，而不是一个“答题器”。这个循环体连接外部世界、内部记忆与执行工具。

\subsection{Agentic Loop 是新手必须手写一次的 Hello World}

Peter 反复强调一个观点：每个做 AI 系统的人都该自己实现一遍 loop。原因不是“重复造轮子”，而是理解自治系统如何在现实中失控或稳定。

\begin{importantbox}{Loop 的教学价值}
\begin{itemize}
    \item 你会看到 context window 如何限制推理连续性；
    \item 你会看到 tool call 如何放大错误；
    \item 你会看到 memory 写入策略如何影响“人格一致性”；
    \item 你会直观看到“系统 prompt 不是墙”，真正的约束在执行路径上。
\end{itemize}
\end{importantbox}

\subsection{Memory 不是“可选增强”，而是身份层}

在 OpenClaw 体系里，memory 文件不是缓存，而是跨会话连续性的核心。访谈中多处提到：若没有 memory，系统每次启动都像“失忆重启”。

\begin{knowledgebox}{Memory 的三层作用}
\begin{itemize}
    \item \textbf{任务层}：保存待办、工具状态、上下文索引；
    \item \textbf{策略层}：保存用户偏好和“少做什么”的约束；
    \item \textbf{身份层}：保存长期语气、价值倾向、行为习惯。
\end{itemize}
其中第三层最容易被忽视，但恰恰决定“这是不是你熟悉的那个 agent”。
\end{knowledgebox}

\begin{warningbox}{Memory 文件可被污染}
只要 memory 在文件系统上，就存在被误写、篡改、注入的风险。一个“看起来更懂你”的 agent，可能只是吸收了错误或恶意的状态信息。
\end{warningbox}

\subsection{Harness 的角色：把能力关进可治理边界}

访谈里对 harness 的描述很实用：它是能力层与权限层之间的“操作系统”。模型能力在这里被转换为可审计、可限制、可回滚的动作。

一个值得注意的设计取舍是：Peter 倾向最小 UI、强调终端可见性。因为复杂 UI 容易掩盖真实执行轨迹，降低 debugging 可解释性。

\subsection{本章小结}
OpenClaw 的技术核心不是单点算法，而是 loop / memory / harness 三者耦合。理解三者关系，是评估任何 agent 系统可靠性的前提。
