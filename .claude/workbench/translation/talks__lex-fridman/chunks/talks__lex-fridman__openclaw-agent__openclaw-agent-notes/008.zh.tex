\section{开发者工作流：终端、提问策略与语言生态}

访谈中另一条主线是“如何与 agent 共写代码”。与常见“prompt 技巧”不同，Peter 的重点是环境组织和提问纪律。

\subsection{终端优先与最小 UI}

他偏好终端是因为可见性高、切换成本低，并能清晰观察 agent 执行轨迹。访谈里提到的误操作案例（在错误目录执行）也说明环境隔离的重要性。

\begin{knowledgebox}{高频工作流细节}
\begin{itemize}
    \item 多终端并行：一部分给 agent，一部分给人工验证；
    \item 先“讨论不写代码”，再显式切执行；
    \item 阅读 agent 反问来判断它缺失了哪些上下文；
    \item 避免把 UI 流程当作质量保证，质量要靠约束与验证。
\end{itemize}
\end{knowledgebox}

\subsection{语言选择：不再是“我喜欢什么”，而是“agent+生态最匹配什么”}

访谈里提到 Go、TypeScript、Python、Rust、Zig 等选择逻辑：更多由生态和部署条件驱动，而非个人语法偏好。

\begin{importantbox}{Agent 时代的语言决策框架}
\begin{itemize}
    \item CLI/部署便捷优先：Go 常是性价比解；
    \item Web 生态优先：TypeScript 迭代快但复杂度高；
    \item AI 推理链路：Python 生态成熟但跨平台部署需谨慎；
    \item 高性能与并发：Rust / Zig 在特定场景更优。
\end{itemize}
\end{importantbox}

\subsection{本章小结}
Agent 时代不会取消工程方法，只会放大方法差异。真正的效率来自“任务分解 + 环境约束 + 验证纪律”，而不是单一模型或单一语言。
