\section{Síntesis y ampliación}

Esta clase mostró la trayectoria evolutiva del verifier. El outcome verifier respalda el best-of-$N$ mediante la etiqueta de la respuesta final; el process reward model mejora la asignación de crédito y la búsqueda mediante supervisión a nivel de paso; Math-Shepherd estima automáticamente el valor de cada paso a partir de la tasa de éxito de los rollouts; Weaver, por su parte, combina múltiples weak verifiers, aprovechando la complementariedad de sus errores para reducir el generation--verification gap, y disminuye el costo mediante destilación.

Estos cuatro métodos responden, cada uno, a una de cuatro preguntas:

\begin{enumerate}
    \item \textbf{¿Es correcto el resultado?} ORM;
    \item \textbf{¿En qué paso comienza el error?} PRM;
    \item \textbf{¿Pueden generarse automáticamente las etiquetas de los pasos?} rollout-based process supervision;
    \item \textbf{¿Cómo combinar múltiples judges poco confiables?} weak supervision ensemble.
\end{enumerate}

La siguiente clase lleva la retroalimentación de «juzgar la respuesta» a «interactuar con herramientas y con el entorno»: ReAct usa los resultados de la observación para corregir el razonamiento, RLEF utiliza la ejecución de código como reward de entrenamiento, y Constitutional AI emplea principios para que el modelo se autocritique y genere AI feedback.
