\section{Direcciones futuras del sistema: hybrid serving, test-time infrastructure y continual learning}

\videofigure{figures/research-directions.jpg}{La investigación futura abarca los principios de aprendizaje de synthetic data, continual learning, y la infraestructura de test-time scaling con alto rendimiento y baja latencia.}{00:52:18--00:57:06}

Test-time scaling ya no es un solo forward pass: incluye muestreo repetido, actualizaciones de agent en múltiples rondas, tool call, reutilización de KV cache, ramas paralelas y verifier. El serving tradicional de chatbot está optimizado para decodificación de una sola ronda y no puede satisfacer automáticamente esta carga de trabajo irregular.

\begin{importantbox}{La infraestructura de inferencia debe percibir el agent graph}
El scheduler necesita ver las dependencias de ramas, los prefix compartibles, las esperas de herramientas y las prioridades de candidatos, para poder optimizar de manera global entre latencia, rendimiento y consumo energético.
\end{importantbox}

\videofigure{figures/intelligence-efficiency-future.jpg}{La siguiente etapa requiere serving híbrido local/cloud, nuevos modelos y kernels, y una medición más fina de intelligence-per-watt.}{00:57:06--00:59:02}

El enrutamiento dinámico puede escribirse como una decisión sensible al costo:

$$
a^*=\arg\min_{a\in\{\text{local},\text{cloud}\}}
\left(C_a+\lambda_L L_a+\lambda_E E_a+\lambda_R R_a\right),
$$

\begin{itemize}
    \item $C_a$: costo monetario;
    \item $L_a$: latencia;
    \item $E_a$: consumo energético;
    \item $R_a$: riesgo de fallo, privacidad o seguridad;
    \item $\lambda$: el peso que la aplicación asigna a cada costo.
\end{itemize}

\subsection{La división de trabajo entre memory y weight update}

La sesión de preguntas y respuestas de la clase aborda el continual learning: actualizar la memory externa es más fácil, más rastreable y menos propenso a dañar las capacidades ya existentes; pero si el objetivo es adquirir un nuevo reasoning skill, una abstracción entre dominios o una generalización de robots entre embodiments distintos, agregar solo memory puede no ser suficiente, y aun así podría necesitarse una actualización de parámetros.

\begin{knowledgebox}{Knowledge acquisition y skill acquisition son distintos}
Una base de datos es adecuada para almacenar hechos, historial y preferencias del usuario; el weight update es más adecuado para cambiar cómo el modelo combina información, cómo actúa y cómo transfiere habilidades. Los sistemas reales deben decidir qué experiencias se escriben en la memory y cuáles entran al entrenamiento.
\end{knowledgebox}

\begin{warningbox}{Un context infinito no es continual learning gratis}
Incluso si se pudieran almacenar todas las experiencias, el modelo podría no ser capaz de recuperarlas y combinarlas con precisión en un context extremadamente largo. Una memory eficaz sigue requiriendo compresión, indexación, estrategias de olvido y manejo de conflictos.
\end{warningbox}

\subsection{Resumen de la sección}

Los futuros sistemas de agent optimizarán simultáneamente el modelo, el serving, el hardware y el mecanismo de aprendizaje: enrutamiento dinámico entre local y cloud, infraestructura que soporte test-time search irregular, memory que conserve experiencias recuperables, y weight update que aprenda habilidades transferibles.
