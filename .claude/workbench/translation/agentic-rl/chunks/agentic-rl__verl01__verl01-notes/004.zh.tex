\section{调参方法：先分层，再定位瓶颈}
面对 veRL 这类训练框架，最常见的问题不是“参数太少”，而是参数分层不清。把模型、算法、训练配置拆开看，才能判断当前性能瓶颈来自模型能力、优势估计，还是 batch/rollout 等训练编排。

\begin{knowledgebox}{推荐的调参顺序}
\begin{itemize}
  \item 先确认模型与 tokenizer 配置正确
  \item 再调算法相关超参数，如 clip、KL、learning rate
  \item 最后调 batch、rollout、accumulation 这类系统参数
\end{itemize}
\end{knowledgebox}

\subsection{本章小结}
参数分层的意义，在于帮助研究者用更低的试错成本找到真正的瓶颈，而不是把所有开关一起乱拧。
