\section{Systematic Debugging（系统化调试）}

\subsection{四阶段流程}

遇到 Bug 或测试失败时触发，\textbf{禁止盲目猜测或试错式修复}：

\begin{enumerate}
    \item \textbf{根因调查}（Root Cause Analysis）：找到真正的原因。
    \item \textbf{模式分析}（Pattern Analysis）：识别重复出现的问题模式。
    \item \textbf{提出假设}（Hypothesis）：基于证据提出修复方案。
    \item \textbf{最小化实现与验证}（Minimal Fix \& Verify）。
\end{enumerate}

\begin{warningbox}{三次循环未解决则架构有问题}
如果上述四阶段循环了三次仍无法解决，说明可能存在架构层面的问题，需要回到 Brainstorming 重新审视设计。
\end{warningbox}

\subsection{完成前验证 Skill}

AI 喜欢"假装完成"或过度自信。此 Skill 要求：在宣布任务完成、测试通过、准备提交之前，必须\textbf{真实运行验证命令}，并根据实际输出来宣称完成。

\subsection{本章小结}

系统化调试用四阶段闭环替代"拍脑袋式"修复，三次未果则升级为架构问题，避免在错误方向上越陷越深。
