\section{Step 1 Prompt 分析：生成初始解}

\subsection{Prompt 结构}

Step 1 的 System Prompt 是一个标准的结构化 Markdown 文本，分为三部分：

\begin{enumerate}
    \item \textbf{核心指令}：
    \begin{itemize}
        \item 严谨性至关重要（IMO 大部分是证明题，最终判据是逻辑严谨性）
        \item 诚实对待结果——不要硬凹（避免 Reward Hacking）
        \item 全文使用 LaTeX
    \end{itemize}
    \item \textbf{输出格式（Adaptive Prompt）}：
    \begin{itemize}
        \item Summary：包含 Verdict（是否找到完整方案）和方法概述
        \item Detailed Solution：详细的解决方案
    \end{itemize}
    \item \textbf{Self-Verification 指令}
\end{enumerate}

\subsection{输出格式的设计意图}

\begin{importantbox}{Verdict 用于分支判断}
Summary 中的 Verdict 不仅是信息展示，更是后续 Workflow 的\textbf{分支判断依据}——如果 Verdict 为 false（未找到完整解），则跳过后续验证，直接重新 sample。Detailed Solution 则送入 Verification 环节。
\end{importantbox}

本文代码使用\textbf{正则表达式}提取这些结构化输出（而非结构化输出 API），因为 Gemini 2.5 Pro 的指令遵循能力足够强。

\subsection{Step 2：Self-Improvement}

Step 2 与 Step 1 \textbf{共享上下文}。其 Prompt 很简单：``你有一个机会改进你的结果——仔细 review 你的 solution，纠正错误，填充 justification gap。''

引入 Step 2 的原因是 Step 1 中 Thinking Budget（32768 tokens）可能被打满，模型被迫仓促结束思考。Step 2 给予模型继续思考的机会。

\subsection{本章小结}

Prompt 设计的精髓在于：结构化输出为后续 Workflow 的分支判断和数据流向提供了基础。
