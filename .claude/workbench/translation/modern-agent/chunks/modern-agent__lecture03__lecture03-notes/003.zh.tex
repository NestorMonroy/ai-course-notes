\section{LangGraph 实现详解}

\subsection{状态定义}

全局共享的状态（State）包含四个字段：
\begin{itemize}
    \item \texttt{input}：用户的问题/任务
    \item \texttt{plan}：形成的 Plan List（sub-goal 序列）
    \item \texttt{past\_steps}：已经执行过的步骤及其结果（追加式）
    \item \texttt{response}：最终给用户的回答
\end{itemize}

\subsection{Plan 节点}

Plan 的 System Prompt 设计非常 general（与具体任务无关）：
\begin{quote}
\textit{For the given objective, come up with a simple step by step plan. This plan should involve individual tasks, that if executed correctly will yield the correct answer. Do not add any superfluous steps. The result of the final step should be the final answer. Make sure that each step has all the information needed -- do not skip steps.}
\end{quote}

输出是结构化的 Steps 列表。

\subsection{Execute 节点}

Execute 使用 ReAct Agent（\texttt{create\_react\_agent}）来消化 Plan 中的每一个 step。一个 step 可能对应多个工具调用。执行结果追加到 \texttt{past\_steps} 中。

\subsection{RePlan 节点}

RePlan 的输入包含三部分：
\begin{enumerate}
    \item 用户的原始目标（objective）
    \item 原始的 Plan
    \item 已经执行过的 steps 及其结果
\end{enumerate}

\begin{warningbox}{RePlan Prompt 的关键约束}
\begin{itemize}
    \item 如果没有更多步骤需要执行，直接 return to user
    \item 否则，只添加仍需执行的步骤到 Plan 中
    \item \textbf{不要返回已经执行过的 steps 作为新 Plan}
\end{itemize}
\end{warningbox}

\subsection{Graph 结构}

三个节点 + 条件边：
\begin{enumerate}
    \item \textbf{Planner} $\rightarrow$ \textbf{Agent}（ReAct Execute）$\rightarrow$ \textbf{RePlan}
    \item RePlan 有一条条件边：决定是结束（response）还是继续执行（回到 Agent）
\end{enumerate}

\subsection{本章小结}

LangGraph 实现展示了如何将 Plan-Execute-RePlan 落地为一个清晰的三节点 Graph，其中 Plan 和 RePlan 决定了整体质量上限，Execute 负责具体的工具调用。
