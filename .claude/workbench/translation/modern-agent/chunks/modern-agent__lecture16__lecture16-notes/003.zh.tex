\section{Apply Patch：结构化的代码编辑}

\subsection{为什么不直接重写文件？}

Apply Patch 是 Codex 中最核心的代码编辑工具。它的设计理念是：\textbf{不让模型自由地重写整个文件，而是输出结构化的 diff}——添加了什么行、删除了什么行、添加了什么文件、删除了什么文件。

\begin{importantbox}{Patch DSL：一种受限的领域特定语言}
Apply Patch 定义了一套基于 Lark 语法的 DSL（Domain Specific Language）：
\begin{itemize}
    \item 使用 \texttt{*** begin patch} / \texttt{*** end patch} 包裹。
    \item 用 \texttt{*** update file} / \texttt{*** add file} / \texttt{*** delete file} 标记操作。
    \item 强制模型以 diff 形式表达编辑意图，而非随意改文本。
\end{itemize}
\end{importantbox}

\subsection{为什么模型能理解 Lark 语法？}

\begin{enumerate}
    \item 在请求体中，Codex 将 Lark Grammar 的文本作为工具描述的一部分发送给模型。
    \item 在第一条 System Instruction 中，也包含了 Apply Patch 的使用说明。
    \item 指令明确要求：\textbf{对单个文件的编辑必须使用 Apply Patch，不要用 Python 读写文件}；当简单的 Shell 命令或 Apply Patch 可以满足时，不要另辟蹊径。
\end{enumerate}

\subsection{Patch 的执行流程}

Handler 收到 Patch 内容后并不立即修改文件，而是：
\begin{enumerate}
    \item \textbf{验证语法}：检查 Patch 是否符合 Lark Grammar。
    \item \textbf{推导影响范围}：确定改了哪些文件、需要哪些读写权限。
    \item \textbf{权限审批}：如有额外审批要求则先获取许可。
    \item \textbf{执行 Patch}：应用 diff 到文件系统。
\end{enumerate}

\subsection{本章小结}

Apply Patch 将"改代码"这一高风险操作约束为结构化的 diff DSL，既节省上下文（不需要输出整个文件），又让每次编辑可审计、可验证。
