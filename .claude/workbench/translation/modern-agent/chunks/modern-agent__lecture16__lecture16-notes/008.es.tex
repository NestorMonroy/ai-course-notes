\section{Síntesis y ampliación}

Esta entrega analizó a fondo, desde la perspectiva del diseño de herramientas, las 12 herramientas predefinidas de Codex; repaso de los puntos centrales:

\begin{enumerate}
    \item \textbf{Arquitectura de tres capas}: especificación interna (Tool Spec) $\rightarrow$ Wire Layer (transporte de red) $\rightarrow$ Handlers (ejecución local).
    \item \textbf{Apply Patch}: un DSL de diffs restringido por una gramática de Lark, que estructura y hace auditables las ediciones de código.
    \item \textbf{Execute Commands + Write Stdin}: cubre tanto la ejecución puntual como las sesiones interactivas.
    \item \textbf{Sistema de subagentes}: gestiona el ciclo de vida de los sub-Agent mediante cinco primitivas (Spawn / Send Inputs / Wait / Close / Resume), logrando aislamiento de contexto y ejecución concurrente.
    \item \textbf{View Image}: la herramienta de puente de imágenes del Agent multimodal, que hace explícito «ver la imagen» como una Function Call.
    \item \textbf{El regreso de la salida de Function Call}: la percepción del modelo sobre el valor de retorno de una herramienta depende por completo de que el Runtime inyecte el resultado en el contexto, no del output\_schema definido en la herramienta.
\end{enumerate}

Al entender el diseño de estas 12 herramientas, sumado al análisis de Context Engineering de entregas anteriores, se puede formar una comprensión profunda e intuitiva del funcionamiento interno de los distintos Coding Agent. La enseñanza central es: \textbf{los límites de capacidad del Agent = la capacidad del modelo subyacente + las herramientas y el contexto que mantiene el Agent Runtime + las restricciones de proceso de la capa del Harness}.
