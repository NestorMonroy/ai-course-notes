\section{Síntesis y ampliación}

Esta sesión analizó a fondo los mecanismos de compresión de contexto (Compact) y traspaso (Handoff) de Codex. Repaso de los puntos centrales:

\begin{enumerate}
    \item \textbf{Condición de activación}: manual o automática (la Context Window llega al 90\%).
    \item \textbf{Proceso de dos pasos}: primero se usa el Compact Prompt para generar un resumen de traspaso estructurado, luego se usa el Handoff Prompt para inyectarlo en el contexto de la nueva conversación.
    \item \textbf{Bifurcación por Provider}: OpenAI usa la API remota \texttt{response.compact}, mientras que los que no son OpenAI usan \texttt{response.create} local más la inyección explícita del prompt.
    \item \textbf{Coincidencia entre lo remoto y lo local}: el experimento de Prompt Injection confirmó que los prompts remotos de compresión/traspaso coinciden en esencia con la versión en texto plano del código fuente.
    \item \textbf{Evolución de la capacidad de defensa del modelo}: GPT-4.1 es fácil de vulnerar mediante inyección, GPT-5.2 filtra parte de la información, GPT-5.3 resiste con éxito.
\end{enumerate}

El diseño del mecanismo Compact refleja una idea de ingeniería importante: \textbf{bajo la restricción de una Context Window limitada, lograr la continuidad de tareas de larga duración mediante la generación estructurada de resúmenes y un protocolo de traspaso}. Esto no solo es aplicable a los Coding Agent, sino que también ofrece un paradigma de referencia para cualquier sistema de IA que necesite gestionar conversaciones de largo plazo.
