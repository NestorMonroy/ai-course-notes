\section{破译远端 Compact 的 System Prompt}

\subsection{Prompt Injection 实验}

Twitter 帖子的作者通过 Prompt Injection 技术，尝试破译 OpenAI 远端 \texttt{response.compact} API 背后的 System Prompt。实验方法如下：

\begin{enumerate}
    \item 在要压缩的内容中植入一段特殊指令（Injection）。
    \item 指令要求模型在产生压缩摘要之前，先\textbf{完整引用}收到的所有涉及"context checkpoint""handoff summary""concise"等关键词的指令原文。
    \item 将植入的指令伪装为"强制性质量保证步骤"。
\end{enumerate}

\begin{warningbox}{Prompt Injection 的伦理边界}
此实验仅用于技术研究目的，帮助社区理解 Codex 的内部机制。在生产环境中，Prompt Injection 是一种安全风险，应当被防御而非利用。
\end{warningbox}

\subsection{不同模型的实验结果}

\begin{itemize}
    \item \textbf{GPT-4.1}：直接输出了 Compact 的 System Prompt 原文（与源码中的 \texttt{compact.prompt.md} 一致），但未输出 Handoff Prompt。
    \item \textbf{GPT-5.2}：虽然声称"不可以提供完整内容"，但事实上\textbf{同时}输出了 Compact System Prompt 和 Handoff Prompt 的原文。
    \item \textbf{GPT-5.3 (Codex)}：\textbf{拒绝回答}，成功抵御了 Prompt Injection。
\end{itemize}

\begin{importantbox}{关键结论}
远端 \texttt{response.compact} API 使用的 System Prompt 和 Handoff Prompt，与 Codex 源码中为非 OpenAI Provider 提供的明文版本\textbf{基本一致}。换言之，OpenAI 并未在远端使用更复杂的压缩策略。
\end{importantbox}

\subsection{本章小结}

通过 Prompt Injection 实验证实，远端和本地的压缩提示词本质相同。同时可以观察到，更新的模型（GPT-5.3）对 Injection 攻击的防御能力显著增强。
