\section{Codex 内置 Tools 全景}

\subsection{Tools Schema 的获取方法}

默认情况下，Codex 的 API 层面 Tools Schema 不会持久化到本地。如果需要查看完整的请求体（包括 Tools 定义），需要设置特定的环境变量来启用日志记录：

\begin{warningbox}{日志落盘方法}
设置环境变量后，Codex 会将完整的 API 请求体保存到本地的 \texttt{logs-1.sqlite} 数据库中。通过查询数据库记录，可以获取到包含 \texttt{instructions}（System Prompt）、\texttt{input}（Message List）和 \texttt{tools}（Tools Schema）的完整请求体。
\end{warningbox}

请求体的结构（Response API 格式）：

\begin{itemize}
    \item \texttt{instructions}：独立的顶层指令，相当于 System Prompt
    \item \texttt{input}：完整的消息列表，可包含 Developer、User、Assistant、Function Call Output 等角色
    \item \texttt{tools}：工具定义列表
    \item Response API 特有的特性：可以挂载之前的 Response ID 进行上下文链接
\end{itemize}

\subsection{Codex 的五类内置 Tools}

通过分析 Codex 的 Tools Schema，可以发现至少五种类型的内置 Function：

\begin{importantbox}{Codex 内置 Tools 分类}
\begin{enumerate}
    \item \textbf{Shell 命令执行}：
    \begin{itemize}
        \item \texttt{execute\_command}：执行 Shell 命令
        \item \texttt{send\_input}：向已有命令会话写入标准输入并读取标准输出
    \end{itemize}
    \item \textbf{计划管理}：
    \begin{itemize}
        \item \texttt{update\_plan}：更新执行计划（所有现代 Coding Agent 都内置 Plan Mode）
    \end{itemize}
    \item \textbf{用户交互}：
    \begin{itemize}
        \item \texttt{request\_user\_input} / \texttt{ask\_user\_question}：向用户询问问题
    \end{itemize}
    \item \textbf{代码操作}：
    \begin{itemize}
        \item \texttt{apply\_patch}：编辑和执行代码
        \item \texttt{view\_image}：查看图片
    \end{itemize}
    \item \textbf{网络与搜索}：
    \begin{itemize}
        \item \texttt{websearch}：网络搜索
    \end{itemize}
\end{enumerate}
\end{importantbox}

\subsection{Multi-Agent（子代理）工具}

Codex 还内置了一套完整的 Multi-Agent 系统工具：

\begin{importantbox}{子代理管理工具}
\begin{itemize}
    \item \texttt{spawn\_agent}：启动一个新的子代理
    \item \texttt{send\_input}：给已有子代理继续发送消息或补充上下文
    \item \texttt{resume\_agent}：恢复上一个已关闭或暂停的子代理
    \item \texttt{wait}：等待一个或多个子代理完成
    \item \texttt{close\_agent}：关闭子代理并返回其最后状态
    \item \texttt{spawn\_agents\_on\_csv}：按 CSV 每行批量启动子代理并汇总结果
\end{itemize}
\end{importantbox}

\begin{knowledgebox}{CSV 批量子代理}
\texttt{spawn\_agents\_on\_csv} 是一个较新的功能，可以根据 CSV 文件的每一行批量启动子代理，每个子代理处理一行数据，最终汇总所有结果。这适用于批量处理类任务，是 Multi-Agent 编排的一种实用模式。
\end{knowledgebox}

\subsection{MCP 作为 Dynamic Tools}

除内置 Tools 外，MCP（Model Context Protocol）提供了动态工具机制：

\begin{itemize}
    \item MCP Tools 取决于用户配置了哪些 MCP Server
    \item 每个 MCP Server 会暴露若干 Tools / Functions
    \item MCP 的 Tools 定义同样通过 API 的 \texttt{tools} 字段暴露给模型
    \item MCP 在配置文件中配置，但其暴露的 Tools Schema 不会出现在 Session 文件中
\end{itemize}

\subsection{本章小结}

Codex 内置五类 Tools（Shell 执行、计划管理、用户交互、代码操作、网络搜索），以及完整的 Multi-Agent 子代理管理工具。MCP 提供动态工具扩展能力。所有 Tools 通过 API 的 tools 字段暴露给模型。
