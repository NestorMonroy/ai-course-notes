\section{总结与延伸}

\begin{enumerate}
    \item Offline RL 在静态数据下优化策略，需要平衡模仿和探索。
    \item 数据集的覆盖度与 reward 质量直接决定方法的鲁棒性。
    \item IQL 通过 expectile V 来隐式约束搜索，CQL 通过 explicit penalty 施加 conservatism。
    \item 多层评估、日志化监控与治理框架是成功部署的关键。
    \item 监测分布 shift、Q variance、action entropy 让部署后风险可控。
\end{enumerate}

\subsection{进一步行动}

\begin{enumerate}
    \item 先用 dataset diagnostics 表识别好/坏轨迹，再决定是 filter、IQL 还是 CQL。
    \item 在部署前构建 replay simulator，通过 replay 复现高风险场景。
    \item 建立 monitor dashboard（action KL、reward gap、Q variance），并给 devops team 明确 alert threshold。
    \item 将每次 policy 更新的 audit info（data version、reward log、human sign-off）写入治理日志。
\end{enumerate}
