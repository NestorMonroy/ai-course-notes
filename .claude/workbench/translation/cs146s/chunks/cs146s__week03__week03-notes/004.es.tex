\section{Síntesis y ampliación}

La semana 3 exploró desde dos perspectivas complementarias el uso óptimo de los IDE de IA y las herramientas de programación: Mihail Eric se centró en la metodología de context engineering (spec doc, optimización del código base, archivos de configuración de Agent), mientras que Silas Alberti presentó, desde el punto de vista de la elección de herramientas, un marco de decisión entre lo síncrono y lo asíncrono.

\subsection{Puntos clave}

\begin{itemize}
    \item Los IDE de IA dependen, en su base, de semantic indexing (embedding + Merkle tree) y de un LLM de infilling
    \item Las tareas complejas requieren un spec doc al estilo de un PM, que incluya goal, plan, source files, edge cases, etc.
    \item Optimizar el código base es más fundamental que optimizar el prompt: se recomienda el diseño de un repositorio único
    \item Tres eras de las herramientas de programación con IA: completion $\rightarrow$ IDE automation $\rightarrow$ cloud agent
    \item Las herramientas síncronas mantienen el flujo de trabajo, las asíncronas permiten la paralelización, evitando la trampa de la ``semi-asincronía''
    \item Las habilidades centrales del futuro: delegar, leer código y planear arquitecturas
\end{itemize}

\subsection{Orden recomendado para la práctica}

\begin{enumerate}
    \item Primero, completar en el repo la documentación de orientation, los comandos de prueba y la descripción de los archivos clave
    \item Después, introducir el IDE de IA para tareas de alta frecuencia y alcance reducido, como preguntas y respuestas, modificaciones de un solo archivo y cambios guiados por spec
    \item Por último, delegar a un Agent asíncrono la programación y las pruebas de cadenas más largas, y formar así un ciclo cerrado de colaboración entre lo síncrono y lo asíncrono
\end{enumerate}
