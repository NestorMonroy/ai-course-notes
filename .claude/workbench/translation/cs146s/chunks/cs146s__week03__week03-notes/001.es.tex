\section{Evolución y capacidades centrales de los IDE con IA}

\subsection{Breve historia de los IDE}

El IDE (Integrated Development Environment) es el entorno de trabajo central del desarrollo de software: integra en uno solo el editor, el compilador, el depurador y otras herramientas. Su evolución refleja la mejora continua de la eficiencia de desarrollo:

\begin{itemize}
    \item \textbf{1983}: Turbo Pascal, el primer IDE verdadero
    \item \textbf{1997}: Microsoft Visual Studio, capacidades avanzadas de depuración (C++/Visual Basic)
    \item \textbf{2001}: IntelliJ IDEA, navegación de código contextual, refactorización, autocompletado de código
    \item \textbf{2015}: VSCode, editor ligero más un ecosistema de extensiones altamente ampliable
    \item \textbf{2023}: Cursor, uno de los primeros IDE nativos de IA de uso extendido
\end{itemize}

\begin{knowledgebox}{El «efecto péndulo» en la evolución de los IDE}
A lo largo de la historia de los IDE ha existido un «efecto péndulo» (see-saw) entre la integración de funciones y la personalización por parte del desarrollador. La aparición de los IDE con IA volvió a inclinar el péndulo hacia la integración de funciones: la incorporación profunda de capacidades de IA en el entorno de desarrollo.
\end{knowledgebox}

\subsection{Modos de uso de los IDE con IA}

\subsubsection{Modo básico (Bread-and-Butter)}

\begin{itemize}
    \item \textbf{Inline}: autocompletado de código en línea
    \item \textbf{Function}: generación a nivel de función
    \item \textbf{Single-file}: edición de un solo archivo
    \item \textbf{Multi-file}: modificaciones entre archivos
\end{itemize}

\subsubsection{Modo nativo de IA}

\begin{itemize}
    \item \textbf{Background Agents}: ejecución autónoma de tareas en segundo plano
    \item \textbf{Integración de MCP}: conexión con herramientas externas mediante el protocolo MCP
    \item \textbf{Memories}: aprende y recuerda las preferencias del usuario y el contexto del proyecto
    \item \textbf{Bugbot / PR Review}: revisión de código automatizada
\end{itemize}

\subsection{Principios subyacentes de los IDE con IA}

\subsubsection{Tab-complete (autocompletado de código)}

\begin{enumerate}
    \item Se envía de forma cifrada al servidor una pequeña context window alrededor del código actual
    \item El servidor ejecuta un LLM de infilling
    \item La sugerencia se devuelve y se muestra en el editor
\end{enumerate}

\subsubsection{Chat (modo de conversación)}

\begin{enumerate}
    \item Los bloques de código se almacenan como embeddings y se construye un semantic index (usando nombres de archivo ofuscados más el código)
    \item Al hacer una consulta el usuario, se recuperan los bloques de código más relevantes y se inyectan como context en el LLM
    \item El IDE reindexa periódicamente los bloques de código y sincroniza los embeddings
    \item El diff de los bloques de código se calcula mediante un Merkle tree, lo que permite actualizaciones eficientes
\end{enumerate}

\begin{importantbox}{Aplicación del Merkle tree en la indexación de código}
El Merkle tree es una estructura de árbol de hashes que se usa comúnmente en Git y en cadenas de bloques. En los IDE con IA, el Merkle tree se usa para detectar de forma eficiente los cambios en el código: solo los bloques de código que cambiaron necesitan recalcular su embedding, lo que evita el costo de reconstruir el índice completo.
\end{importantbox}

\subsection{Resumen de la sección}

Los IDE con IA incorporan el LLM de manera profunda en el flujo de trabajo de desarrollo mediante dos modos: tab-complete y chat. Su funcionamiento depende de la semantic indexing del código y de un mecanismo eficiente de actualización incremental. Entender estos principios ayuda a aprovechar mejor las capacidades de los IDE con IA.
