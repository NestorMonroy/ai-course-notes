\section{Panorama rápido del funcionamiento de los LLM}

\subsection{Arquitectura básica}

Un LLM (Large Language Model) es un modelo autorregresivo (autoregressive) de predicción del siguiente token (next-token prediction). Su flujo de trabajo básico es:

\begin{enumerate}
    \item \textbf{Tokenization}: usar un vocabulario fijo para dividir el texto de entrada en tokens
    \item \textbf{Embedding}: convertir cada token en un vector numérico de dimensión fija (por lo general de 1K a 3K dimensiones)
    \item \textbf{Transformer layers}: pasar por 12--96+ capas de Transformer (que usan el mecanismo de self-attention, Vaswani et al. 2017)
    \item \textbf{Distribución de probabilidad de salida}: generar, sobre el vocabulario, la distribución de probabilidad del siguiente token
\end{enumerate}

\begin{knowledgebox}{El núcleo de la arquitectura Transformer}
El mecanismo de self-attention permite que el modelo, al generar cada token, «vea» todos los demás tokens de la secuencia de entrada, capturando así dependencias de largo alcance. Esta es la base técnica clave que permite que un LLM entienda el contexto del código.
\end{knowledgebox}

\subsection{Proceso de entrenamiento: paradigma de tres etapas}

El entrenamiento de los LLM modernos suele seguir un paradigma de tres etapas:

\textbf{Stage 1: Self-supervised Pretraining}
\begin{itemize}
    \item Preentrenamiento autosupervisado sobre grandes cantidades de datos públicos
    \item Las fuentes de datos incluyen Common Crawl, Wikipedia, StackExchange, repositorios públicos de GitHub, entre otras
    \item Escala de datos: de cientos de miles de millones a billones o más de tokens (lenguaje y código)
    \item Objetivo: aprender la estructura básica del lenguaje y conocimiento del mundo
\end{itemize}

\textbf{Stage 2: Supervised Fine-tuning (SFT)}
\begin{itemize}
    \item Enseñar al modelo a seguir instrucciones
    \item Entrenamiento con pares prompt-response de alta calidad
    \item Escala de datos: de decenas de miles a cientos de miles de pares
    \item Ejemplo: «Write a for loop» $\rightarrow$ «ok here's a for loop...»
\end{itemize}

\textbf{Stage 3: Preference Tuning (RLHF/DPO)}
\begin{itemize}
    \item Alinear la salida del modelo con las preferencias humanas (helpfulness, correctness, readability)
    \item Recolectar múltiples salidas para un mismo prompt y entrenar un reward model que prediga la preferencia humana
    \item Escala de datos: de decenas de miles a cientos de miles de pares de comparación anotados por personas
\end{itemize}

\begin{importantbox}{La evolución de los reasoning models}
Sobre la base de estas tres etapas, los reasoning models amplían aún más el entrenamiento: incorporan chain-of-thought reasoning traces, integración del uso de herramientas, recolección de preferencias humanas sobre los pasos de razonamiento, y el aprendizaje, mediante aprendizaje por refuerzo (RL), de cómo evaluar las trazas de razonamiento y retroceder (backtrack).
\end{importantbox}

\subsection{Ventajas y limitaciones de programar con LLM}

\textbf{Ventajas}:
\begin{itemize}
    \item Autocompletado de código de nivel experto (expert-level)
    \item Comprensión y explicación de código
    \item Corrección de código (bug fixing)
\end{itemize}

\textbf{Limitaciones}:
\begin{itemize}
    \item \textbf{Hallucination}: genera API inexistentes u obsoletas (se puede mitigar con context engineering robusto)
    \item \textbf{Límite de context window}: $\sim$100--200K tokens, pero no todos los tokens son igual de efectivos
    \item \textbf{Latencia}: cada solicitud tarda desde segundos hasta minutos (hay que planear la delegación de tareas en función de esto)
    \item \textbf{Costo}: en los mejores modelos, los tokens de entrada cuestan \$1--3/M y los de salida \$10+/M
\end{itemize}

\begin{warningbox}{El problema de calidad de la Context Window}
Aunque los LLM modernos afirman soportar context windows de 100K a 200K tokens, la investigación muestra que la atención del modelo hacia la información situada en la parte media de la ventana cae de forma notable (el fenómeno «lost in the middle»). No basta con meter todo el contenido posible en el context y esperar buenos resultados.
\end{warningbox}

\subsection{Resumen de la sección}

Un LLM es, en esencia, un modelo de predicción del siguiente token (next-token prediction) que, mediante un entrenamiento de tres etapas (preentrenamiento $\rightarrow$ SFT $\rightarrow$ alineación de preferencias), adquiere una gran capacidad de generación de código. Entender su funcionamiento y sus limitaciones es un requisito para usar con eficacia las herramientas de programación con IA.
