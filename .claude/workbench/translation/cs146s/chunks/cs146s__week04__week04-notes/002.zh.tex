\section{嘉宾讲座：Claude Code 的设计哲学 (Boris Cherny)}

\subsection{编程正处于拐点}

Claude Code 的创造者 Boris Cherny 分享了一个关键洞察：编程语言和 IDE 的生产力都在沿指数曲线增长，而 AI 正是驱动最新一波增长的核心力量。

\begin{knowledgebox}{编程生产力的指数增长}
从 Assembly 到 FORTRAN，从 C 到 Python，从 VS Code 到 Cursor/Claude Code——每一代编程语言和 IDE 都在对数尺度上实现了生产力的线性提升。验证（verification）技术也在同步演进：从手动调试到静态类型，从自动化测试到 AI 驱动的 fuzz testing 和 self-play。
\end{knowledgebox}

\subsection{Claude Code 的设计原则}

Claude Code 的核心设计哲学是三个``无处不在''：

\begin{enumerate}
    \item \textbf{Terminal-native}：在终端中运行，而非 IDE 插件
    \item \textbf{Low-level model access}：提供对底层模型的直接访问
    \item \textbf{Infinitely hackable}：无限可定制
\end{enumerate}

\subsection{一个 Claude Code，多种形态}

Claude Code 以多种形态服务不同场景：

\begin{itemize}
    \item \textbf{Terminal}：命令行直接使用
    \item \textbf{IDE}：集成到 VS Code 等编辑器
    \item \textbf{Web \& iOS}：通过 \url{claude.ai/code} 访问
    \item \textbf{GitHub App}：通过 \texttt{/install-github-app} 安装
    \item \textbf{SDK}：程序化调用，支持 JSON 输出、管道组合
\end{itemize}

\subsection{Claude Code 的典型使用模式}

\subsubsection{代码库问答与调研}

\begin{itemize}
    \item ``How do I make a new ValidationTemplateFactory?''
    \item ``Why did we fix issue \#18363 by adding the if/else in login.ts?''
    \item ``Look at PR \#9383, then verify which app versions were impacted''
    \item ``What did I ship last week?''
\end{itemize}

\subsubsection{工作流适配任务}

不同任务适合不同的工作流模式：
\begin{itemize}
    \item \textbf{explore $\rightarrow$ plan $\rightarrow$ confirm $\rightarrow$ code $\rightarrow$ commit}：适合需要调研的 bug fix
    \item \textbf{tests $\rightarrow$ commit $\rightarrow$ code $\rightarrow$ iterate $\rightarrow$ commit}：TDD（测试驱动开发）模式
    \item \textbf{code $\rightarrow$ screenshot $\rightarrow$ iterate}：UI 开发的视觉迭代模式
\end{itemize}

\subsubsection{快速原型迭代}

Boris 展示了一个生动的原型迭代案例：通过连续的自然语言指令，快速迭代 TODO 列表的 UI 设计——从最初的工具使用显示，到内联标题，到独立面板，再到与 spinner 合并显示，每次迭代只需一条 prompt。

\begin{importantbox}{为 6 个月后的模型而构建}
Boris 强调的核心理念：不要为今天的模型能力设计你的工作流，而要为\textbf{6 个月后}的模型能力做准备。模型在快速进化，你的工具和工作流也应该具备演进能力。
\end{importantbox}

\subsection{管理多个 Agent 时的组织约束}

Week 4 的另一个隐含结论是：当开发者开始同时管理多个 Agent，项目管理方式本身也要变化。

\begin{itemize}
    \item \textbf{任务必须可切分}：如果需求本身模糊不清，就很难安全委派给多个 Agent 并行执行
    \item \textbf{边界必须清晰}：每个 Agent 负责哪些文件、哪些验证步骤、哪些提交粒度，需要事先说清
    \item \textbf{审查必须标准化}：越依赖 Agent 并行，越需要一致的 diff 审查和回滚机制
\end{itemize}

\begin{warningbox}{Agent Manager 的主要失败模式不是模型不聪明，而是任务切分不合理}
很多并行失败并非因为 Agent 做不到，而是因为人类在开始前没有给出清晰的责任边界和验收标准。换言之，Agent Manager 首先是项目管理能力，然后才是 prompt 技巧。
\end{warningbox}

\subsection{本章小结}

Claude Code 的设计哲学是 terminal-native、低层模型访问和无限可定制。它覆盖了从代码库调研到 CI/CD 管理的整个 SDLC。核心使用策略是根据任务类型选择合适的工作流模式，并为未来的模型能力提前做好准备。
