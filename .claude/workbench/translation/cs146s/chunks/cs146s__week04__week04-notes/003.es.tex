\section{Síntesis y ampliación}

La semana 4 abordó los patrones de uso de Coding Agent desde dos perspectivas complementarias: Mihail Eric explicó la metodología y las técnicas de gestión de Agent Manager, mientras que Boris Cherny compartió, desde la perspectiva del creador de Claude Code, la filosofía de diseño de herramientas y su experiencia práctica.

\subsection{Puntos clave}

\begin{itemize}
    \item El desarrollo de software está pasando de «personas que gestionan personas» a «personas que gestionan Agents»: esta es la cuarta transformación de la forma organizacional
    \item Cuatro técnicas para dirigir a los Agents: archivos de comportamiento, hooks, commands y subagents
    \item Prácticas clave: barreras de protección (tests + CI/CD), marcas de auditoría, adecuación del modelo a la tarea, checkpoints frecuentes
    \item Filosofía de diseño de Claude Code: terminal-native, low-level access e infinitely hackable
    \item Elegir el flujo de trabajo según el tipo de tarea: explore-plan-code, TDD e iteración visual
    \item Prepararse para las capacidades del modelo de dentro de 6 meses
\end{itemize}

\subsection{Lista de implementación}

\begin{enumerate}
    \item Crear commands, hooks y archivos de comportamiento reutilizables para las tareas comunes
    \item Usar subagents para las tareas paralelas con una división de trabajo clara, en lugar de meter todo el trabajo en un mismo contexto
    \item Tratar los tests, el CI y la revisión humana como límites estrictos del flujo de trabajo del Agent, no como un remedio posterior
\end{enumerate}

\subsection{Modelo de madurez de adopción en equipos}

Del contenido del curso se puede extraer una ruta de adoption muy práctica:

\begin{enumerate}
    \item \textbf{Periodo de experimentación individual}: ingenieros concretos usan el Agent para preguntas y respuestas, código de andamiaje y refactorizaciones locales
    \item \textbf{Periodo de normalización en equipo}: comienza a consolidarse un conjunto de commands, hooks, reglas de review y archivos de comportamiento unificados
    \item \textbf{Periodo de colaboración en paralelo}: el Agent se usa en tareas multihilo con una división de trabajo clara, y los desarrolladores empiezan a asumir el rol de Agent Manager
    \item \textbf{Periodo de integración del sistema}: el flujo de trabajo del Agent se integra a fondo con el CI, la revisión de código, la base de conocimiento y las herramientas de gestión de proyectos
\end{enumerate}

\begin{knowledgebox}{El indicador de que aumenta la madurez no es «usar más Agents», sino «que los fallos sean más controlables»}
Los equipos que en verdad llegan a la etapa de madurez no son los que se ven más vistosos, sino aquellos en los que, cuando el Agent comete un error, los tests, los hooks, la revisión de código y los límites de responsabilidad lo detectan a tiempo con mayor facilidad. Por eso Boris y Mihail insisten una y otra vez en los guardrails, y no solo en la velocidad.
\end{knowledgebox}
