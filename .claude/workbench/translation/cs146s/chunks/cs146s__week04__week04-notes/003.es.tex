\section{Síntesis y ampliación}

Week 4 exploró los patrones de uso de Coding Agent desde dos perspectivas complementarias: Mihail Eric explicó la metodología y las técnicas de gestión de Agent Manager, mientras que Boris Cherny, desde la perspectiva del creador de Claude Code, compartió la filosofía de diseño de herramientas y la experiencia práctica.

\subsection{Puntos clave}

\begin{itemize}
    \item El desarrollo de software está pasando de «personas que gestionan personas» a «personas que gestionan Agents» — esta es la cuarta transformación de la forma organizacional
    \item Cuatro técnicas de orientación para Agents: archivos de comportamiento, hooks, commands y subagents
    \item Prácticas clave: barreras de protección (tests + CI/CD), etiquetado de auditoría, coincidencia entre tarea y modelo, y checkpoints frecuentes
    \item Filosofía de diseño de Claude Code: terminal-native, low-level access, infinitely hackable
    \item Elegir el flujo de trabajo según el tipo de tarea: explore-plan-code, TDD, iteración visual
    \item Prepararse para las capacidades del modelo de dentro de 6 meses
\end{itemize}

\subsection{Lista de implementación}

\begin{enumerate}
    \item Establecer commands, hooks y archivos de comportamiento reutilizables para las tareas comunes
    \item Usar subagents para las tareas paralelas con una división de trabajo clara, en lugar de apretar todo el trabajo en un solo contexto
    \item Tratar las pruebas, el CI y la revisión humana como límites estrictos del flujo de trabajo de Agent, y no como un remedio posterior
\end{enumerate}

\subsection{Modelo de madurez de adopción en equipos}

Del contenido del curso se puede extraer una ruta de adoption muy práctica:

\begin{enumerate}
    \item \textbf{Periodo de experimentación individual}: ingenieros concretos usan Agents para resolver preguntas, generar código de andamiaje y hacer refactorización local
    \item \textbf{Periodo de estandarización en equipo}: se empiezan a consolidar commands, hooks, reglas de review y archivos de comportamiento unificados
    \item \textbf{Periodo de colaboración paralela}: los Agents se usan en tareas multihilo con una división de trabajo clara, y los desarrolladores comienzan a asumir el papel de Agent Manager
    \item \textbf{Periodo de integración del sistema}: el flujo de trabajo de Agent se integra profundamente con el CI, la revisión de código, las bases de conocimiento y las herramientas de gestión de proyectos
\end{enumerate}

\begin{knowledgebox}{El indicio de una mayor madurez no es «usar más Agents», sino «que las fallas sean más controlables»}
Los equipos que realmente alcanzan la etapa de madurez no son los que se ven más vistosos, sino aquellos en los que, cuando un Agent comete un error, este se detecta a tiempo mediante pruebas, hooks, revisión de código y límites de responsabilidad bien definidos. Por eso Boris y Mihail insisten repetidamente en los guardrails, y no solo en la velocidad.
\end{knowledgebox}
