\section{Síntesis y ampliación}

La semana 4 exploró los patrones de uso de los Coding Agents desde dos perspectivas complementarias: Mihail Eric explicó la metodología y las técnicas de gestión del Agent Manager, mientras que Boris Cherny compartió, desde la perspectiva del creador de Claude Code, la filosofía de diseño de herramientas y la experiencia práctica.

\subsection{Puntos clave}

\begin{itemize}
    \item El desarrollo de software está pasando de ``personas que administran personas'' a ``personas que administran Agents''; esta es la cuarta transformación de la forma organizacional
    \item Cuatro técnicas de orientación para Agents: archivos de comportamiento, hooks, commands, subagents
    \item Prácticas clave: barreras de protección (tests + CI/CD), marcas de auditoría, coincidencia de modelos, checkpoints frecuentes
    \item Filosofía de diseño de Claude Code: terminal-native, low-level access, infinitely hackable
    \item Elegir el flujo de trabajo según el tipo de tarea: explore-plan-code, TDD, iteración visual
    \item Prepararse para las capacidades del modelo dentro de 6 meses
\end{itemize}

\subsection{Lista de implementación}

\begin{enumerate}
    \item Crear commands, hooks y archivos de comportamiento reutilizables para las tareas comunes
    \item Usar subagents para procesar tareas paralelas con una división de trabajo clara, en lugar de apretar todo el trabajo en un solo contexto
    \item Tratar las pruebas, la CI y la revisión humana como límites estrictos del flujo de trabajo del Agent, no como un remedio posterior
\end{enumerate}

\subsection{Modelo de madurez de adopción en equipos}

Del contenido del curso se puede extraer una ruta de adoption muy práctica:

\begin{enumerate}
    \item \textbf{Etapa de experimentación individual}: algunos ingenieros usan Agents para responder preguntas, generar código de andamiaje y hacer refactorizaciones locales
    \item \textbf{Etapa de estandarización del equipo}: se comienzan a consolidar commands, hooks, reglas de review y archivos de comportamiento unificados
    \item \textbf{Etapa de colaboración paralela}: los Agents se usan en tareas de múltiples hilos con una división de trabajo clara, y los desarrolladores comienzan a asumir el rol de Agent Manager
    \item \textbf{Etapa de integración de sistemas}: el flujo de trabajo de los Agents se integra a fondo con la CI, la revisión de código, las bases de conocimiento y las herramientas de gestión de proyectos
\end{enumerate}

\begin{knowledgebox}{La señal de que aumenta la madurez no es ``usar más Agents'', sino ``que las fallas sean más controlables''}
Los equipos que realmente entran en la etapa de madurez no son los que se ven más vistosos, sino aquellos en los que, cuando un Agent comete un error, este es capturado a tiempo por las pruebas, los hooks, la revisión de código y los límites de responsabilidad. Por eso Boris y Mihail insisten repetidamente en los guardrails, y no solo en la velocidad.
\end{knowledgebox}
