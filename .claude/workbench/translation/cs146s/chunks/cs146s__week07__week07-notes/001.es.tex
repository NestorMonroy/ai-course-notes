\section{El valor y los métodos de la revisión de código}

\subsection{Por qué la revisión de código es la actividad de ingeniería de mayor apalancamiento}

La revisión de código (Code Review) es una de las actividades de mayor apalancamiento para mejorar la capacidad de ingeniería individual y la calidad del código del equipo. Los datos lo respaldan:

\begin{importantbox}{El valor cuantificado de la revisión de código}
\begin{itemize}
    \item La tasa de detección de errores de la revisión de código es de 55--60\%, mientras que la de los distintos modos de prueba es de apenas 25--45\%
    \item Tasa de errores del programa sin revisión de código frente a con revisión de código: 4.5 $\rightarrow$ 0.82 errors/100 lines
    \item Un estudio de AT\&T mostró que la revisión de código aporta un aumento de productividad de 14\% y una reducción de defectos de 90\%
\end{itemize}
\textit{Fuente: Coding Horror}
\end{importantbox}

\subsection{En qué debe enfocarse la revisión de código}

\subsubsection{Errores de lógica y de corrección}

¿El código funciona según lo esperado? ¿Hay condiciones de frontera mal manejadas, errores off-by-one, etcétera?

\subsubsection{Legibilidad y mantenibilidad}

¿El código es fácil de entender y de modificar después? ¿Los nombres son claros? ¿Cada función tiene una única responsabilidad?

\subsubsection{Rendimiento}

¿Hay consultas a la base de datos innecesarias, problemas de N+1, o una complejidad de tiempo o espacio poco razonable?

\subsubsection{Seguridad}

¿Existen riesgos de seguridad como SQL injection, XSS, entradas sin validar, fuga de datos sensibles, etcétera?

\subsubsection{Mejores prácticas}

¿Se siguen las convenciones de estilo, los patrones de diseño y las convenciones de arquitectura del proyecto?

\subsection{Qué es una buena revisión de código}

\begin{warningbox}{``This won't work'' no es un buen comentario de revisión}
Una simple negación no aporta ningún valor pedagógico. Un buen comentario de revisión debe ser constructivo, específico e invitar al diálogo. Por ejemplo:

``I see your new method matches the existing style in this file, taking {[}X{]} parameters. Having that many parameters hurts readability and implies the function is doing too much. What do you think about refactoring this method and the existing ones in a later pull request to reduce how many parameters they take?''
\end{warningbox}

\subsection{Resumen de la sección}

La revisión de código es la garantía central de la calidad del software, y su tasa de detección de errores supera con creces a la de las pruebas automatizadas. Un buen comentario de revisión debe ser específico, constructivo, y ofrecer una oportunidad de aprendizaje a la persona revisada.
