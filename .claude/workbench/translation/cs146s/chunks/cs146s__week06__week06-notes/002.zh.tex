\section{三大漏洞检测技术}

\subsection{SAST：静态应用安全测试}

\begin{itemize}
    \item \textbf{白盒}测试技术，分析源代码和二进制文件
    \item 在 SDLC 早期执行，此时发现和修复的成本最低
    \item 可识别：SQL injection、command injection、XSS
    \item 核心技术：基于模式匹配的代码库扫描
\end{itemize}

\begin{knowledgebox}{``Shift Left'' 安全理念}
SAST 体现了``shift left''安全理念——将安全检查尽可能前移到开发生命周期的早期。在代码编写阶段就发现漏洞，修复成本远低于在生产环境中发现后再修复。AI 让这一理念比以往更容易实践。
\end{knowledgebox}

\subsection{DAST：动态应用安全测试}

\begin{itemize}
    \item \textbf{黑盒}测试技术，模拟真实攻击者的行为
    \item 可贯穿整个 SDLC，假阳性率较低
    \item 可识别：SQL injection、broken authentication、XSS
    \item 核心技术：
    \begin{itemize}
        \item Input fuzzing（输入模糊测试）
        \item Session token manipulation（会话令牌操纵）
        \item Configuration/header testing（配置/头部测试）
        \item Brute force rate-limit tests（暴力破解速率限制测试）
    \end{itemize}
\end{itemize}

\subsection{SCA：软件组成分析}

\begin{itemize}
    \item 深度分析应用使用的 OSS 包
    \item 分析包管理器、infrastructure-as-code、拉取的镜像
    \item 核心技术：
    \begin{itemize}
        \item 分析包元数据的依赖关系
        \item 传递依赖解析（transitive dependency resolution）
        \item 匹配已知漏洞数据库
        \item 二进制/artifact 扫描
    \end{itemize}
\end{itemize}

\subsection{本章小结}

SAST、DAST、SCA 三种技术互补：SAST 在早期通过代码分析发现漏洞，DAST 在运行时模拟攻击，SCA 分析第三方依赖的安全性。完整的安全策略需要三者结合。
