\section{总结与延伸}

\subsection{课程的核心信息}

CS146S 这门课的核心信息可以归结为一句话：\textbf{AI 正在改变软件开发的每一个环节，但优秀工程师的核心价值——理解力、判断力和品味——不仅不会被取代，反而变得更加珍贵}。

Martin Casado 作为 a16z 的 General Partner，从投资人的视角为我们提供了一个更宏观的思考框架。他在 VMware 和 Nicira 的创业经历证明：真正的技术革命不是替代人类，而是\textbf{放大人类的能力}。AI 软件工程也不例外。

\begin{importantbox}{终极展望}
十年后的软件开发者将不再``写''代码——他们将\textbf{设计}、\textbf{指导}、\textbf{审查}和\textbf{编排}软件的创建。编码将成为一种``低级操作''，由 AI Agent 完成，就像今天的编译器把高级语言转换为机器码一样。但就像编译器没有取代程序员一样，AI Agent 也不会取代软件工程师——它们只是将``软件工程''的含义提升到了一个新的抽象层次。
\end{importantbox}

\subsection{关键要点}

\begin{itemize}
    \item 五大趋势：意图驱动开发、Agent 管理、工具整合、安全重构、软件民主化
    \item 核心不变：业务理解、架构思维、品味、代码阅读、沟通能力
    \item AI 放大人类能力而非替代人类
    \item ``Software engineering'' 的含义将提升到新的抽象层次
    \item 现在是拥抱快速实验的最佳时机
\end{itemize}

\subsection{个人行动路线}

\begin{enumerate}
    \item 在未来 3 个月内建立一套稳定的 AI 编程工作流，而不是只零散试用工具
    \item 把测试、安全、review 和文档一起纳入 AI 工作流，而不是只优化写代码速度
    \item 主动训练自己做规划、委派和系统审查，这些会比纯编码更快成为稀缺能力
\end{enumerate}

\subsection{未来岗位分化的可能形态}

如果把整门课的判断再往前推一步，软件行业内部可能出现新的岗位重心分化：

\begin{itemize}
    \item \textbf{AI Workflow Engineer}：专门设计 Agent 工作流、行为文件、工具链和验证层
    \item \textbf{System Reviewer / Architect}：更专注于审查系统边界、接口契约和长期演进方向
    \item \textbf{AI-Native Product Builder}：兼具产品、设计和工程能力，快速完成从需求到原型再到上线
\end{itemize}

\begin{warningbox}{岗位不会简单减少，而是重新组合}
AI 可能减少某些低层重复编码工作，但会同时放大规划、审查、集成、安全和组织设计的重要性。对个人而言，真正的风险不是“AI 会不会写代码”，而是自己是否仍停留在只会执行低层任务的角色里。
\end{warningbox}
