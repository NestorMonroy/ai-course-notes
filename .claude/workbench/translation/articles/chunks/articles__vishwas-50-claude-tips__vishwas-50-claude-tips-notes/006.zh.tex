\section{权限、安全与 Hooks}
%% ============================================================

Hooks 是 Claude Code 中确定性最高的控制机制，适合处理"必须每次都执行"的规则。

\subsection{CLAUDE.md 是建议，Hooks 是规则（Tip \#38）}

\begin{importantbox}{CLAUDE.md vs Hooks 的本质区别}
CLAUDE.md 是建议性的，Claude 大约 80\% 的时间会遵守。Hooks 是确定性的，100\% 执行。如果某件事必须无条件发生（格式化、lint、安全检查），用 Hook；如果是 Claude 应该考虑的指导方针，用 CLAUDE.md。
\end{importantbox}

\subsection{用 /permissions 白名单化安全命令（Tip \#33）}

不要再对 \texttt{npm run lint} 点一百次"approve"了。\texttt{/permissions} 让你将信任的命令加入白名单，不在列表中的命令仍然会弹出确认。

\subsection{用 /sandbox 隔离运行（Tip \#34）}

\texttt{/sandbox} 启用操作系统级隔离：文件写入限制在项目目录，网络请求限制在你批准的域名。macOS 使用 Seatbelt，Linux 使用 bubblewrap。

\begin{knowledgebox}{无人值守场景}
对于过夜迁移、实验性重构等无人值守任务，推荐在 Docker 容器中运行 Claude。容器提供完全隔离和轻松回滚。
\end{knowledgebox}

\subsection{PostToolUse Hook：自动格式化（Tip \#39）}

每次 Claude 编辑文件后自动运行格式化工具：

\begin{lstlisting}[caption={PostToolUse Hook 配置（.claude/settings.json）}, language=bash]
# PostToolUse hook
npx prettier --write "$CLAUDE_FILE_PATH" || true
\end{lstlisting}

\texttt{|| true} 防止格式化失败阻塞 Claude。注意：如果编辑器同时打开了相同文件，建议关闭 format-on-save，因为编辑器保存可能使 prompt cache 失效。

\subsection{PreToolUse Hook：拦截危险命令（Tip \#40）}

用 PreToolUse Hook 拦截 \texttt{rm -rf}、\texttt{DROP TABLE}、\texttt{TRUNCATE} 等危险命令。Hook 在执行前触发，危险命令不会被实际执行。

可以通过 \texttt{/hooks} 交互式设置，或直接告诉 Claude："Add a PreToolUse hook that blocks rm -rf, drop table, and truncate commands."

\subsection{Notification Hook：跨 Compaction 保留上下文（Tip \#41）}

长会话中 compaction 可能导致 Claude 丢失当前工作的上下文。设置一个 \texttt{Notification} hook，在 compaction 触发时自动重新注入关键信息：

\begin{itemize}
  \item 当前任务描述
  \item 已修改的文件列表
  \item 硬性约束条件（如"不要修改 migration 文件"）
\end{itemize}

\subsection{Stop Hook：完成时播放提示音（Tip \#48）}

添加 Stop hook，Claude 完成响应时播放系统提示音。启动任务后切换到其他工作，听到提示音再回来查看。

\subsection{始终手动 Review 关键逻辑（Tip \#42）}

\begin{warningbox}{人工审核不可省略的场景}
无论 Claude 生成的代码看起来多好，以下领域必须人工审核：
\begin{itemize}[nosep]
  \item 认证/授权流程（Auth flows）
  \item 支付逻辑（Payment logic）
  \item 数据变更/删除操作（Data mutations）
  \item 破坏性数据库操作（Destructive DB operations）
\end{itemize}
错误的 auth scope、配置错误的支付 webhook、或静默删除列的 migration 可能造成用户流失、资金损失或信任危机。
\end{warningbox}

\subsection{本章小结}

安全控制的层次结构：\texttt{/permissions} 管理命令白名单 $\to$ \texttt{/sandbox} 提供系统级隔离 $\to$ PreToolUse Hook 拦截危险操作 $\to$ PostToolUse Hook 自动格式化 $\to$ Notification Hook 保留上下文。CLAUDE.md 管建议，Hook 管规则，关键逻辑必须人工审核。
