\section{Coding Agent: de problemas de competencia a ingeniería real}

\subsection{La evolución de la serie Coder}

Lin Junyang (林俊旸) señala que los modelos de Coding actuales son esencialmente distintos de los del pasado:

\begin{itemize}
    \item \textbf{Antes}: resolver problemas de competencia (se da el enunciado, se produce la Solution) — corresponde a Live Code Bench
    \item \textbf{Ahora}: Software Engineering (se revisa un GitHub issue, se propone un PR que lo corrige) — corresponde a SWE-Bench
\end{itemize}

\begin{importantbox}{La esencia de la programación al estilo Agent}
El proceso de mantener un repositorio de GitHub parece simple, pero en realidad implica interacción con el entorno en múltiples turnos: abrir la carpeta, leer los nombres de los archivos, entender la estructura del código, localizar el problema, modificar el código, ejecutar las pruebas... Esto es precisamente el núcleo de un Agent: \textbf{la interacción en múltiples turnos con el entorno}.
\end{importantbox}

Qwen Coder alcanza entre 67 y 69 puntos en SWE-Bench (versión de julio) y también tiene un desempeño sobresaliente en bases de referencia de tareas de CLI como Terminal-Bench. Más importante aún: estas capacidades de Coding ya se han integrado en el modelo general más grande (con más de 1T de parámetros), que también alcanza alrededor de 69 puntos en SWE-Bench.

\begin{knowledgebox}{Diferencias culturales de Coding entre China y Estados Unidos}
Al regresar del área de la bahía, Lin Junyang (林俊旸) percibió una diferencia interesante: el fundador de Cognition (Devin) dijo que ``en San Francisco ya nadie escribe código a mano, todos hacen vibe coding''. Pero en China, la difusión del vibe coding todavía no es tan alta. Sin embargo, se llega al mismo destino por caminos distintos: el objetivo de todos es lograr que la IA produzca productividad real.
\end{knowledgebox}

\subsection{La transformación del paradigma de entrenamiento: Agent RL}

\begin{importantbox}{El nuevo paradigma del entrenamiento de Agent}
El entrenamiento del Coding Agent de Qwen ya no consiste en el etiquetado tradicional de pares de entrada y salida, sino en lo siguiente:
\begin{enumerate}
    \item Definir un Schedule (una cola de tareas de entrenamiento)
    \item Desplegar el Agent (LM + Scaffold) en un entorno Docker
    \item El Agent opera de forma autónoma en el entorno (abre archivos, edita código, ejecuta pruebas, etc.)
    \item Otorgar una señal de reward según el resultado
    \item Destruir el entorno y pasar a la siguiente ronda
\end{enumerate}
Esto es, en sentido estricto, Multi-turn RL with Environment Feedback: no solo es un reto algorítmico, sino que también implica una gran cantidad de ingeniería de Infra (gestión de Docker, entrenamiento paralelo, sincronización de estado, etc.).
\end{importantbox}

\begin{knowledgebox}{Optimización conjunta de algoritmo e Infra}
En el pasado, la ``optimización conjunta de algoritmo e Infra'' solía considerarse un simple gancho publicitario, pero en la era del entrenamiento de Agent es \textbf{una necesidad real}. Además de la mejora en la eficiencia del entrenamiento que menciona DeepSeek, el entrenamiento de Agent requiere un soporte considerable de Infra para la gestión de entornos, lo cual ya excede el ámbito de capacidad de un equipo puramente algorítmico.
\end{knowledgebox}

\subsection{Resumen de la sección}

El Coding Agent representa un cambio de paradigma de ``resolver problemas'' a ``ingeniería''. Qwen entrena sus modelos en entornos reales mediante Agent RL e integra las capacidades de Coding en un modelo grande unificado. En el futuro, la evaluación también debería pasar de las bases de referencia estáticas a tareas dinámicas del mundo real.
