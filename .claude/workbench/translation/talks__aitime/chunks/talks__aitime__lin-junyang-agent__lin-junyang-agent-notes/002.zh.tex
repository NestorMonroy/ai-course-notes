\section{Qwen3 文本模型：Reasoning 的自然化}

\subsection{千问三系列的核心升级}

相比被广泛使用的 Qwen 2.5，千问三的主要提升包括：

\begin{enumerate}
    \item \textbf{整体能力提升}：作为新一代基座模型的全面进化
    \item \textbf{Reasoning 能力跃升}：这是 2024--2025 年最显著的变化
    \item \textbf{多语言支持}：支持 119 种语言及方言
    \item \textbf{长上下文}：已做到 1M+ token，内部实验已达数 M 级别
\end{enumerate}

\subsection{Reasoning 的自然化之路}

\begin{importantbox}{Thinking 与 Instruct 的统一}
林俊旸分享了一个重要的市场信号：在 4 月份发布 Thinking+Instruct 合并版本后，\textbf{超过 90\% 的客户放弃了单独的 Thinking 模型}，回到了 Instruct 模型。原因是：
\begin{itemize}
    \item 用户最初喜欢看模型的``自我对话''（thinking trace），但这种新鲜感很快消退
    \item Instruct 模型更实用，响应更自然
    \item 关键是如何让 Reasoning 能力\textbf{自然地融入}到 Instruct 模型中
\end{itemize}
\end{importantbox}

Qwen 团队在 7 月份推出了改进版本，核心做法是：对于 Reasoning-intensive 的任务，将 Thinking 过程集成到回答本身中，而非使用独立的 thinking token。效果是 AIME 等数学基准从约 20 分提升到约 70 分（Thinking 模型可达 90 分），客户反馈模型``明显聪明了很多''。

\begin{knowledgebox}{DeepSeek R1 的启示与反思}
DeepSeek R1 展示了通过``絮絮叨叨的自我对话''可以让模型变强，但 Qwen 团队认为这不是最终形态。他们追求的是\textbf{更自然的 Reasoning}——模型在需要深度思考时确实会思考，但不会用冗长的内心独白打扰用户体验。
\end{knowledgebox}

\subsection{多语言：从韩语到乌尔都语}

多语言支持的起源是一个有趣的故事：

\begin{enumerate}
    \item 最初 Qwen 只做了中英双语
    \item 一位韩国研究者说``你们的模型完全不懂韩语''，选择了 Mistral 作为基座
    \item 调查发现 Pretrain 模型其实会韩语，只是 Post-train 没有覆盖
    \item 顺手修复后，全球用户开始涌入
    \item 巴基斯坦用户反复请求支持乌尔都语——``我们真的没有大模型可用''
    \item 目前已支持 119 种语言，但非洲语言覆盖仍不足
\end{enumerate}

\begin{warningbox}{数字鸿沟的现实}
林俊旸提到，非洲很多地区至今仍在使用功能机。如果做大模型的想法不是帮助全人类，``那还不如不做''。这一理想主义立场驱动了 Qwen 持续扩展语言覆盖的努力。
\end{warningbox}

\subsection{长上下文与 Memory}

\begin{knowledgebox}{Context Length 与 RAG 的关系}
林俊旸引用了 Gemini 长序列团队 leader 的观点：Context Length 和 RAG 本质上是\textbf{正交的}。
\begin{itemize}
    \item 不应该把大量``垃圾''塞入长上下文
    \item 更长的上下文为更好的记忆管理提供了基础
    \item Qwen 已做到 1M+ token，内部实验达数 M 级别
    \item 改变模型架构（Qwen3-Next）的动机之一就是探索 infinite long context 的可能
\end{itemize}
\end{knowledgebox}

\subsection{本章小结}

Qwen3 文本模型的核心进步在于将 Reasoning 能力自然地融入 Instruct 模型中，同时扩展多语言支持和长上下文能力。``让模型聪明但不烦人''是产品化的关键平衡。
