\section{Observabilidad y prácticas de depuración}
\subsection{Registro y pipeline de monitoreo}
Para que cada ejecución del Agent sea rastreable, OpenHands abstrae la terminal, el navegador, las pruebas y los registros en un flujo unificado de eventos. Cada evento incluye una marca de tiempo, la herramienta invocada, una instantánea del contexto y el resultado esperado, lo que facilita a los ingenieros localizar el punto de la falla.

\begin{itemize}
    \item Registro de la terminal: registra cada comando de shell y su código de retorno, y se sube junto con los resultados de las pruebas.
    \item Interacción del navegador y de la red: captura clics, envíos de formularios y solicitudes-respuestas, lo que facilita reproducir sesiones HTTP y flujos de API.
    \item Diff de archivos/código: guarda automáticamente los fragmentos de diff de las modificaciones del Agent, las rutas de los archivos relacionados y el contexto.
\end{itemize}

\subsection{Modo de depuración y reversión rápida}
Cuando el Agent planea ejecutar un comando de alto riesgo (como una publicación o una migración de base de datos), el sistema entra automáticamente en modo de depuración: pausa el proceso, captura la instantánea actual y notifica el comando a un humano para su confirmación. Si la ejecución del comando falla, la plataforma puede revertirlo automáticamente con base en los registros y el diff, evitando contaminar la rama principal.

\begin{knowledgebox}{Recomendaciones de depuración}
Hacer que el Agent registre la «intención» y el «resultado esperado» de cada paso puede acelerar la investigación humana y generar muestras de entrenamiento.
\end{knowledgebox}

\begin{warningbox}{El uso indebido de los registros puede filtrar información sensible}
Los registros de depuración pueden contener API Key, path, stack, por lo que deben configurarse la anonimización de datos y los permisos de acceso, para evitar filtrar información privada durante las auditorías.
\end{warningbox}

\subsection{Resumen de la sección}
\begin{itemize}
    \item Mediante un flujo unificado de eventos y registros con plantilla, es posible acotar rápidamente el alcance de una falla.
    \item El modo de depuración ofrece una doble garantía: confirmación humana y reversión automática.
\end{itemize}
