\section{RLEF：从代码执行反馈中强化学习}

\subsection{代码环境为何特别适合 RL}

代码生成具有明确动作和观察：动作是提交或修改代码，观察是编译结果、测试输出与错误日志。与人类偏好相比，执行反馈便宜、可重复、接近客观，并能自动扩展到大量问题。

\videofigure{figures/rlef-contributions.jpg}{RLEF 将代码作为动作、执行结果作为 observation，构建端到端 RL。}{00:28:00--00:30:08}

\subsection{交互式训练框架}

RLEF 中，policy 生成程序；沙箱运行公开或私有测试；反馈返回给模型，模型可进行多轮修复；episode 结束后根据测试通过情况计算 reward，并用 PPO 更新 policy。

\videofigure{figures/rlef-framework.jpg}{RLEF 的探索、执行反馈、轨迹收集与 policy update。}{00:30:08--00:31:08}

可将 episode 表示为：

$$
\tau=(c_0,o_0,c_1,o_1,\ldots,c_T,o_T),
$$

其中 $c_t$ 是第 $t$ 轮代码输出或修改，$o_t$ 是执行反馈。终局 reward 可写为：

$$
R(\tau)=\frac{1}{M}\sum_{j=1}^{M}\mathbf 1[\mathrm{test}_j(c_T)=\mathrm{pass}].
$$

\begin{itemize}
    \item $M$：测试用例数；
    \item $R(\tau)$：最终代码通过测试的比例；
    \item 私有测试可减少模型针对公开测试硬编码的风险。
\end{itemize}

\subsection{Hybrid Token / Turn-Level Policy}

代码 Agent 的动作既包含 token 级生成，也包含 turn 级“提交、运行、修改”决策。RLEF 将两类粒度结合：token 概率决定代码内容，turn reward 反映完整执行结果。

\videofigure{figures/hybrid-policy.jpg}{PPO 同时处理 token 生成与多轮执行反馈。}{00:31:08--00:34:28}

PPO 的抽象目标为：

$$
\max_\theta\;\mathbb E_t\left[
\min\left(r_t(\theta)A_t,
\operatorname{clip}(r_t(\theta),1-\epsilon,1+\epsilon)A_t\right)
\right],
$$

\begin{itemize}
    \item $r_t(\theta)=\pi_\theta(a_t\mid s_t)/\pi_{\theta_{\rm old}}(a_t\mid s_t)$；
    \item $A_t$：执行反馈导出的 advantage；
    \item $\epsilon$：限制单次 policy 更新幅度的 clipping 系数。
\end{itemize}

\subsection{随着执行反馈扩展的性能}

\videofigure{figures/rlef-scaling.jpg}{RLEF 训练后的 solve rate 随可用执行反馈提升。}{00:34:28--00:36:24}

反馈不仅用于训练，也改变推理时行为。模型学会根据错误类型进行针对性修改，而不是每轮完全重写代码。

\videofigure{figures/rlef-generalization.jpg}{RLEF 对 CodeContests、HumanEval+ 与 MBPP+ 的推理行为和泛化。}{00:36:24--00:36:54}

\videofigure{figures/multiturn-feedback.jpg}{多轮 execution feedback 逐步修复前一轮错误。}{00:36:54--00:39:22}

\begin{importantbox}{Execution feedback 同时是 verifier 与 curriculum}
测试结果判断当前程序是否正确；错误日志还指出模型下一轮应学习什么。随着训练推进，容易错误减少，policy 会遇到更难的边界案例，环境自然形成自适应 curriculum。
\end{importantbox}

\subsection{Reward Hacking 与测试覆盖}

如果 reward 只来自有限测试，模型可能写出特判、利用沙箱漏洞或生成超时但侥幸通过的程序。需要：

\begin{itemize}
    \item 隐藏测试与动态生成测试；
    \item 资源限制、网络隔离和确定性沙箱；
    \item 正确性之外加入效率、安全、可读性等约束；
    \item 对训练期间发现的 exploit 做回归测试。
\end{itemize}

\begin{warningbox}{测试通过只证明“满足测试”，不证明程序正确}
Unit tests 是规范的有限采样。测试覆盖不足时，RL 会系统性寻找未覆盖区域。训练用测试若泄漏到模型上下文，还会把问题退化为记忆或硬编码。
\end{warningbox}

\subsection{本章小结}

RLEF 将代码执行环境变成可扩展 reward source，让模型不仅在当前轨迹中修复错误，还能通过 PPO 把修复策略写入参数。其上限由测试质量、沙箱安全与 reward 设计决定。
