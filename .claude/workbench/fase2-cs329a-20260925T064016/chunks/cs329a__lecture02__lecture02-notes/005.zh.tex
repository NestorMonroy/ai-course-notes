\section{Archon：搜索 Inference-Time Architecture}

\subsection{把推理系统视为可搜索架构}

Archon 不再手工选择单一技巧，而是把 inference-time operations 当作神经网络中的层，搜索它们的组合、顺序、模型来源和调用次数。

\videofigure{figures/archon-framework.jpg}{Archon 根据目标 benchmark 和可用模型搜索优化后的推理架构。}{00:45:47--00:48:36}

其输入包括目标任务、候选模型、可用操作和成本约束；输出是一张执行图。例如多个 generator 并行采样，critic 识别缺陷，ranker 选择候选，fuser 综合答案，再进行下一轮批评与融合。

\subsection{Fusion 为什么可能超过 oracle selection}

Oracle selection 只能从现有候选中挑一个完整答案；fuser 可以从多个不完整候选中提取互补信息，生成一个原候选集合中不存在的新答案。

\videofigure{figures/fusion-results.jpg}{Rank-then-fuse 在部分任务上优于只选择单一候选。}{00:51:20--00:54:58}

\begin{warningbox}{“超过 oracle”并不违反定义}
这里的 oracle 只是在原始候选中选择正确答案；fusion 会执行新的模型调用并生成新候选，因此它改变了候选空间。它不是一个更强的选择器，而是额外的生成步骤。
\end{warningbox}

\subsection{自然语言单元测试}

对于缺少可执行 ground truth 的任务，Archon 让模型生成自然语言测试或约束，再用它们检查候选回答。这相当于先把模糊目标分解为可局部验证的规格。

\videofigure{figures/natural-language-tests.jpg}{自然语言 unit tests 把任务要求转换成可检查条件。}{00:55:30--00:56:24}

这种做法提升了结构化验证能力，但测试由模型生成，仍可能遗漏关键需求。最稳妥的使用方式是把用户明确要求、领域规则和模型生成测试合并，而不是完全依赖自生成规格。

\subsection{深层推理架构与架构搜索}

\videofigure{figures/archon-architectures.jpg}{Archon 搜索出的多层 generator--critic--ranker--fuser 结构。}{00:56:24--00:59:32}

架构空间会随层数、操作类型、模型选择和超参数组合爆炸。Archon 使用贝叶斯优化，以较少试验预测哪些配置最可能提升目标指标。

\videofigure{figures/bayesian-search.jpg}{贝叶斯优化比随机或贪心搜索更高效地发现高性能架构。}{00:59:32--01:01:20}

若配置为 $a$，目标函数可写成多目标效用：

$$
J(a)=\mathrm{Quality}(a)-\lambda_c\mathrm{Cost}(a)-\lambda_l\mathrm{Latency}(a).
$$

\begin{itemize}
    \item $\mathrm{Quality}(a)$：目标 benchmark 上的准确率或偏好分；
    \item $\mathrm{Cost}(a)$：模型调用和 token 成本；
    \item $\mathrm{Latency}(a)$：关键路径延迟；
    \item $\lambda_c,\lambda_l$：部署场景对成本与延迟的权重。
\end{itemize}

\subsection{本章小结}

Archon 把“prompt engineering”提升为系统架构搜索：不只优化一句 prompt，而是优化多个模型调用之间的数据流、控制流和成本。其局限是搜索结果可能过拟合 benchmark，且复杂架构的延迟、可解释性和维护成本显著提高。
